The mechanism

One engine can be confidently wrong.

Most tax software computes a number and shows it to you. You have no way to tell a right answer from a plausible one. So Regal computes everything twice, in code written to disagree — then refuses to ship anything the two versions don't match on.

When they agree

The package unlocks for review. A CA reads the evidence beside the computation — FMV certificate, FX rate, statute, rule version — and approves it by hand. Nothing exports without that signature.

Engine A = Engine Bpackage: approvable

When they disagree

The package locks. The approve endpoint returns a refusal, the mismatch is written to the audit log, and the exact line that diverged is shown. No override, no "approve anyway."

Scope

The honest edges.

Software that files your taxes for you is software you can't check. Regal draws the line deliberately.

Regal does

  • Ingest the cap table from Carta CSV, with row-level errors surfaced
  • Read the merchant-banker FMV certificate, then ask a human to confirm it
  • Lock the FX rate to the exercise date, with the source attached as evidence
  • Compute the perquisite and itemised TDS in exact decimals — never floats
  • Generate every form, and keep an append-only audit trail of who approved what

Regal does not

  • File anything on your behalf, or move money — you deposit, we generate
  • Let AI touch a number: it reads the certificate, and nothing else
  • Guess an FX rate when the exact date is missing — the event gets flagged instead
  • Automate FEMA — exposure is flagged and tracked for a human to act on
  • Allow an override on a locked package, for anyone, including admins
